# Limitations

* **Synthetic data only.** All people, clinicians, clinics, appointments and lab results are fictional. Variants are real ClinVar records assigned to fictional people.
* **Content pending accredited review.** Condition cards, explanations, Teach Back items, options and consent wording were written for the prototype and must be reviewed by accredited clinicians, genetic counsellors and Arabic language reviewers before any real use.
* **Simulated integrations.** Lab delivery (signed bundle in an encrypted inbox), appointment booking, the counsellor directory and authentication (persona picker instead of UAE Pass) are simulated.
* **Blind Couple Match scope.** Matching runs on the partners' devices and the server only relays blinded points, but the prototype server still stores each person's encrypted result at rest. A modified client could submit up to 8 chosen genes (see the PSI threat model in SECURITY.md). Cardinality only mode and synchronised reveal are not built. Shared genes are matched by gene, so the couple view names every condition linked to that gene.
* **Risk engine scope.** Autosomal recessive couple risk only. X linked, dominant, phase unknown and homozygous findings are routed to a counsellor rather than computed. Residual risk after a negative result is explained in words, not computed. Alpha thalassaemia arrangements require a counsellor.
* **Hosting and data residency.** The live demonstration runs on Vercel (Frankfurt) with a Neon database in AWS eu-central-1, because Azure credits were not available in time. That is outside the UAE, so the live site must hold synthetic data only. The intended production home is Azure UAE North; the infrastructure files are ready but have not been deployed.
* **Public demonstration site.** Anyone with the link can sign in as any synthetic persona; there is no real authentication. Protections are a passcode on the demo reset, rate limits on the Copilot (per visitor by network address, so people sharing one address share a limit), and an automatic nightly reset. Changes one visitor makes are visible to others until the reset. Vercel's free plan is for non commercial use, limits how long a request may run, and runs scheduled jobs once a day at an approximate time.
* **Audit truncation.** Deleting the newest audit entries is not detectable until the head hash is anchored externally (planned with Azure immutable storage). Demo reset deliberately restarts the chain.
* **Genetic Copilot.** The live site uses Claude through the Anthropic API; local development and CI use an offline demo model. Claude passed the golden set once (54 of 54, see docs/AI_EVALUATION_CLAUDE.md), which is a single run of a draft test set, not a clinical validation. The public site caps questions at 20 per visitor per hour and 300 per day; beyond that the Copilot declines until the window resets. The golden set and Safety Verifier phrase lists are drafts pending review by a genetic counsellor and Gulf Arabic reviewers. Retrieval is lexical, not embedding based. Conversations are not stored, so the Copilot has no memory between visits.
* **Living Results.** The demo reclassification is simulated. The live ClinVar check exists (`pnpm variant-watch`) and is defined as a nightly Azure Container Apps job in `infra/main.bicep`, which has not been deployed yet. The amended signed report is produced by the prototype playing the lab.
* **Family Risk Engine.** Carrier frequencies are illustrative and unverified. Consanguineous pedigrees use a documented approximation. The family map is a 2D drawing, not the 3D scene in DESIGN.md.
* **Find Care.** Every provider, clinic and coordinate is fictional. Map tiles come from OpenStreetMap and need an internet connection. Distance is straight line, measured from a chosen city centre, not from the person's location.
* **Video sessions are simulated.** The room shows both participants but uses no camera or microphone. Real calls need Azure Communication Services, which is not provisioned yet.
* **Session summaries.** With the offline model the draft only wraps the counsellor's notes in a standard opening and closing. Values Summary is not built because Values Compass is not built.
* **Voice.** The Copilot can be asked by voice and can read answers aloud. Without an Azure AI Speech key it uses the browser's own speech features, which vary by device and are not Gulf Arabic specific. The Azure path (`ar-AE`, `en-US`) is unit tested with a mocked service but **has not been run against a real Azure Speech resource**. The microphone needs https or localhost, so voice questions do not work when the app is opened over plain http from a phone on Wi-Fi. Spoken questions are limited to 20 seconds. Voice exists only in the Copilot; the stored "listen" preference does not yet read other screens aloud.
* **Population Signals.** The dashboard runs on 2,000 synthetic journeys with invented rates; nothing in it is an observation about a real population. SURE and distress figures are synthetic only, because the live Values Compass and Distress Check are not built. Differential privacy is a tested in house implementation (discrete Laplace, sequential composition), not an audited library such as OpenDP; it protects one journey over one quarter at ε 6, uses floating point arithmetic to sample noise, and has not had an external privacy review. The seeded demo release uses a fixed random seed so the walkthrough is repeatable; releases published from the screen use a secure random source. Live events are attributed to Abu Dhabi because personas have no home region. The Living Results list under "Live operations" hides counts under 10 but is an operational view, not a differentially private one. The demand forecast is a simple trend model for planning, and the staffing hint assumes 15 sessions per counsellor per week.
* **Azure deployment.** The Bicep template compiles and the deploy workflow is written, but neither has been run against a real subscription. See docs/DEPLOYMENT.md.
* **Accessibility.** Built to WCAG AA contrast and keyboard use; a full Lighthouse and screen reader audit is pending.
* **Kinship estimates (Phase 5)** will be approximations and counsellor only.
